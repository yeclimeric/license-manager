## 2. S6 遗留：数据齐备但门没上锁

S6 交付了完整的 RBAC 数据与菜单过滤，但**接口本身没有任何权限校验** —— 任何登录用户都能调 `/api/v1/roles`。

### 2.1 发现另一个失效的门

```go
// AdminOnlyMiddleware 原实现
if role != "administrator" { 拒绝 }
// 而 users.role 实际取值：admin / operator / viewer
```

`/v1/admin/system/info` 无人可通过。这道门**从来没打开过**。

### 2.2 权限中间件设计

| 决策 | 理由 |
| --- | --- |
| 校验失败按拒绝处理 | 鉴权故障不能成为放行通道 |
| 通配权限 `*` 放行 | 超管无需枚举全部权限码 |
| `/menus` 不设门 | 任何登录用户都要读自己的菜单 |
| 批量创建按 `create` 权限 | 一次最多发 100 个码，不能当作一次创建 |
| 校验器直查关联表 | 避免 middleware 反向依赖 service 层 |

### 2.3 状态码修正

`100006`（无资源访问权限）原落在 `10` 前缀的 401 分支。**权限不足应为 403**，已加入 `StatusForbidden` 映射。

## 3. S7 企业版实测契约

### 3.1 激活

```
POST /api/v1/activate
{ "authorization_code": "...", "hardware_fingerprint": "..." }
→ {
    "license_key": "LIC-DEVICE-XXXX",
    "license_file": "<base64>",
    "heartbeat_interval": 300,
    "public_key": "<PEM 451字节>"
  }
```

### 3.2 许可证文件结构（实测解开）

```json
{
  "algorithm": "RSA-PSS-SHA256",
  "data": "{ ...payload JSON字符串... }",
  "signature": "<base64>"
}
```

外层 base64 编码。**`data` 是字符串而非嵌套对象** —— 本项目原实现已与此一致。

payload 字段（实测 13 项）：

```
license_key, authorization_code, authorization_code_id,
hardware_fingerprint, deployment_type, start_date, end_date,
max_activations, status, activated_at, generated_at, config_updated_at
```

### 3.3 心跳

```
POST /api/v1/heartbeat
{ "license_key": "...", "hardware_fingerprint": "..." }
→ { "status", "config_updated", "license_file", "heartbeat_interval" }
```

## 4. 产品级签名（S4 密钥的真正用途）

### 4.1 改造前

许可证用**配置文件里的全局密钥**签名 —— 所有产品共用一把私钥。客户端拿到任意产品的公钥，都能验证其他产品的许可证。

### 4.2 改造后

```
授权码 → 关联产品项 → 取该产品私钥 → 签名
激活响应 → 同时下发该产品公钥
```

**实测闭环**：产品公钥验签通过、篡改内容被拒、跨产品验签失败。

**兜底**：未关联产品项、或产品项无密钥（升级前创建）时回退全局密钥 —— 不因密钥问题阻断激活。

## 5. 心跳补强（不复制企业版缺陷）

**实测企业版心跳的两个缺陷**：

| 场景 | 企业版响应 | 本项目 |
| --- | --- | --- |
| 错误硬件指纹 | `200` 成功 | `300008` 拒绝 |
| 授权码已锁定 | `200` 成功 | `300003` 拒绝 |

企业版心跳只看 `license_key` 是否存在，不校验指纹、不感知锁定与过期。

**这意味着复制 license_key 到另一台机器可以继续心跳** —— 客户端若把心跳成功当作「继续运行」，被吊销的许可证永远不会失效。

本项目三项校验全部补上：

| 校验 | 错误码 |
| --- | --- |
| 硬件指纹匹配 | `300008`（已有） |
| 授权码未锁定 | `300003`（已有） |
| 未过结束日期 | `300016`（新增） |

**新增 `300016`**：`300010` 已被「配置参数错误」占用。

## 8. 实施中的问题

### 8.1 替换函数签名留下孤儿代码

用脚本改 `signLicenseFile` 签名时，新函数插入位置在旧函数体中间，导致旧尾部变成顶层孤立代码块 —— 编译报 `expected declaration, found licenseWithSignature`。

**教训**：批量替换函数签名后必须 `go build` 验证，不能只看替换数量。

### 8.2 同名参数遮蔽

`GenerateLicenseFile` 内用的是 `license.AuthorizationCode` 而非 `authCode`。全局替换后该函数编译失败。

### 8.3 测试文件放错包

临时验证测试写在 `internal/service/` 下却声明 `package utils`，报 `found packages service and utils`。改包名时 `gofmt -w` 已重排过内容，`perl` 匹配失败 —— 改用 `sed -i '' '1s/.*/package service/'` 按行号替换。

### 8.4 错误码撞号

想用 `300010` 表示「许可证已过期」，但该码已被「配置参数错误」占用。改为 `300016`。

**教训**：新增错误码前必须先 grep 确认未占用。

- **许可证设备台账未实现**：企业版有 `device_ledger` 资源与 `/devices` 菜单，社区版未种。
