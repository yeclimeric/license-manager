
## 3. 核心设计

### 3.1 菜单存 i18n 键而非文本

`name_key = "menu.product_management"`，前端用 `t(key)` 解析。切换语言时侧边栏标签随之变化，无需改数据库。

### 3.2 通配权限

`super_admin` 持有 `"*"`。菜单树与权限校验都识别通配，避免为超管枚举全部权限。

### 3.3 角色与菜单的保护规则

| 保护 | 错误码 | 理由 |
| --- | --- | --- |
| 内置角色不可删 | `600003` | 内置角色是系统前提 |
| 已分配用户的角色不可删 | `600004` | 否则用户失去全部权限 |
| 内置菜单不可删改类型/路径/权限 | `600008` | 归属系统 |
| 有子菜单不可删 | `600009` | 避免孤儿节点 |
| 已绑定角色的菜单不可删 | `600010` | 角色会指向不存在的菜单 |
| 菜单层级成环 | `600012` | 树构建会无限递归 |
| 未知权限码 | `600015` | 无效权限看起来像已授权 |

**校验顺序**：内置判断先于「是否被引用」，否则运营会看到「已绑定角色」而误以为可先解绑再删。

### 3.4 树构建的三个防御

| 场景 | 处理 |
| --- | --- |
| 子菜单全被过滤的目录 | 整组不显示（空目录像坏菜单） |
| 父菜单不可见时的子菜单 | 不浮到顶层 |
| 环形引用 | 递归深度上限 5，退化为空树 |

均以单测覆盖（`rbac_repository_test.go`，7 项）。

## 4. 修复的项目级缺陷（重要）

### 4.1 `contextKey` 类型键从未被取值方使用

```go
// setter 存的是类型化键
context.WithValue(ctx, UserIDKey, userID)   // UserIDKey 是 type contextKey = "user_id"

// getter 读的是字面量字符串
ctx.Value("user_id")   // ← 永远取不到！
```

`context.WithValue` 以**键的类型与值共同比较**，类型化键与字符串键不相等。

**症状**：`/api/v1/menus` 对有效 token 返回 `{"list":[],"total":0}`，**没有任何报错** —— 因为取到的 userID 是空串，服务层认为「没登录」，返回空树。

**修复**：
1. getter 改用 `UserIDKey` / `UsernameKey`（已补该键与 `WithUsername`）
2. auth 中间件额外注入到 `c.Request.Context()` —— handler 侧 `WithLanguage` 会把 `*gin.Context` 包装为普通 context，原有的类型断言失效

**连带影响**：授权码 service 一直记录空创建人，同一原因，一并修复。

## 7. 实施中的问题

### 7.1 `contextKey` 类型键不匹配（见第 4 节）

最隐蔽的一类：编译通过、测试通过、接口返回 200，只是数据恒为空。

**教训**：写 `context.WithValue` 时，setter 与 getter 必须用**同一个键变量**，任何一边写字面量都会静默失效。

### 7.2 `buildMenuTree` 忘记 append

初版构建根节点时只 `continue` 过滤，却从未把结果 append 回去 —— 返回空数组。单测直接暴露。

**这条是单测的直接价值**：手测只看到「侧边栏空了」，不会想到是树构建丢数据。

### 7.3 前端把分组目录过滤掉了

`toNavItems` 写了 `filter(item => item.path)`，把 path 为空的分组目录直接丢弃 —— 侧边栏只剩 3 个平铺项，分组全没了。

改为「有路径 **或** 有子菜单」才保留。

**教训**：分组目录本身没有路径是**设计**，不是数据缺失。

### 7.4 表格包虚拟根节点多出空行

菜单页原本用 `:data="[tree]` + 虚拟根节点，表格多出一条空白首行。改为直接以顶层菜单作为行数据源。

### 7.5 误以为图标不存在而覆盖已有文件

`UsersIcon.vue` / `MenuIcon.vue` 其实早已存在，我用 `Write` 覆盖后 build 失败，`git checkout` 报 pathspec 不匹配（因为我删掉了）。

**教训**：新增图标前先 `ls` 确认，不要凭印象。

### 7.6 i18n 表头键写漏

`rbac.table.nameKey` 在初版脚本里写成 `rbac.table.nameKey` 但没进 `table` 对象，页面直接显示 `menu.name_key` 字面量。截图发现。

## 8. 遗留

- **接口未做权限校验**：RBAC 数据齐备，但后端路由未挂 `RequirePermission` 中间件 —— 任何登录用户仍可调 `/api/v1/roles`。
- **用户管理页未接角色绑定 UI**：`GET/PUT /api/v1/users/:userId/roles` 就绪，用户页未加入角色分配入口。
- **菜单图标为占位**：seed 用 Material Symbols 名称（`DataLine`/`Box` 等），前端映射到既有 7 个图标，`users`/`menu` 复用 `UserIcon`。
- **权限码未用于路由守卫**：前端未按 `permission` 控制按钮级显隐，目前只有菜单级过滤。
