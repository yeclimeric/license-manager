## 2. 企业版实测契约

### 2.1 公开配置

```
GET /api/public/config     （无需认证）
```

```json
{
  "auth.show_username_password": "true",
  "system.favicon_url": "...",
  "system.logo_url": "...",
  "system.show_copyright": "false",
  "system.site_name": "软件授权管理系统"
}
```

**扁平点号键，值为字符串。** 本项目 seed 的 5 个公开键与其**完全一致**。

### 2.2 API Key

```
POST /api/v1/api-keys  { name(必填), user_id(必填), expires_at, allowed_ips }
```

明文格式：`sk-` + 32 位十六进制 = **67 字符**（实测确认）。

创建响应含 `api_key`（完整对象）+ `api_key` 字段的明文；列表仅含 `api_key_prefix`（`sk-` + 8 位）。

## 3. 核心设计

### 3.1 种子只在缺失时补

```go
var existing models.SystemConfig
err := DB.Where("config_key = ?", key).First(&existing).Error
if err == nil { continue }  // 已存在则跳过，不覆盖
```

**运营在界面改过的值不该被重启冲掉。** 这与 S6 菜单 seed 的处理一致。

### 3.2 API Key 只存哈希与前缀

| 存储 | 用途 |
| --- | --- |
| `key_hash`（SHA-256） | 认证比对 |
| `api_key_prefix` | 列表辨识 |
| 明文 | **仅创建时返回一次** |

**数据库泄露不等于全部密钥泄露。**

### 3.3 过期每次现算，不用定时任务

```go
if key.ExpiresAt != nil && key.ExpiresAt.Before(time.Now()) { 拒绝 }
```

若靠定时任务改 `status` 字段，任务未跑时密钥会**继续可用**。列表状态同样现算。

### 3.4 IP 白名单支持 CIDR

空 = 不限制；非空支持精确 IP 与 `203.0.113.0/24`。非法 CIDR / 非法 IP 一律拒绝（不放行）。

### 3.5 双认证并行

`X-API-Key` 头通过后 `AuthMiddleware` **不再要求 JWT** —— 持有密钥的调用方不应被要求同时持有登录令牌。两种凭据都解析为同一个 `user_id`，下游无需分支。

### 3.6 批量保存配置

配置页同时编辑多个键。逐项保存会产生中间态，且部分失败时状态难以回滚。**一次提交整份**，且**预检所有键存在**（静默跳过不存在的键会让调用方误以为保存成功）。

## 6. 实施中的问题

### 6.1 GORM 默认列名与契约不符

`KeyPrefix` 未标注 `column` 时 GORM 生成 `key_prefix`，而契约是 `api_key_prefix`。补 `column:api_key_prefix` 后 AutoMigrate **新建**了该列，旧列成为 NOT NULL 无默认值的残留，导致插入报 `Error 1364`。

**修复**：新增一次性迁移 `dropLegacyAPIKeyPrefixColumn`，删除旧列（该表当时无真实密钥）。

**教训**：JSON tag 不影响 GORM 的列名推导，两者要分别确认。改列名时必须同时处理残留旧列。

### 6.2 `group` 是 MySQL 保留字

```go
Order("group ASC, sort_order ASC, config_key ASC")   // Error 1064
```

必须反引号转义：`Order("\`group\` ASC, ...")`。

### 6.3 API Key 通过后仍被 AuthMiddleware 拦下

中间件链中 `APIKeyAuthMiddleware` 已认证通过，但 `AuthMiddleware` 仍要求 JWT，返回 401。

**修复**：在 `AuthMiddleware` 开头检查 `auth_type == "api_key"` 则放行。

### 6.4 前端 i18n 键写错表达式

误写 `t('apiKeys.form.deleteKey' as never)`。已补齐 `deleteKey` / `editLabel` 三语文案。

### 6.5 插入脚本块时定位失败

`const { t } = useI18n()` 实际是 `const { t, locale } = useI18n()`，替换未命中；`onMounted(loadRememberedUsername)` 也不是 `onMounted(() => {` 形式。

**教训**：改已有文件前先 grep 确认真实写法，不要凭印象构造替换串。
