## 2. 核心设计

### 2.1 标识符生成与保护

标识符被客户端 SDK 读取并写入许可证，必须稳定且符合变量命名约定。

| 场景 | 行为 |
| --- | --- |
| 留空 | 按名称自动生成：`Pro Version` → `pro_version` |
| 显式传入 | 校验格式（仅小写字母/数字/下划线，以字母开头） |
| 纯中文名 | 拒绝并提示手动填写：`510006` |
| 超长名称 | 截断 + 8 位随机后缀，避免同前缀冲突 |
| 编辑时 | 请求结构不含该字段，服务层回填原值 |

**实测**：

```
POST {"name":"Pro Version"} → identifier: pro_version
POST {"name":"功能模板"}      → 200 + 510006 名称无法转换
POST {"name":"Bad","identifier":"Bad-Name"} → 200 + 510005 格式无效
```

### 2.2 分类保护

企业版实测的 4 个内置分类已按原样 seed，固定 ID 保证多实例不重复插入。

| 分类 | value | 内置 | 可删除 |
| --- | --- | --- | --- |
| 通用 | `general` | ✅ | ❌ |
| 传感器 | `sensor` | ✅ | ❌ |
| 通信 | `communication` | ✅ | ❌ |
| 其他 | `other` | ✅ | ❌ |

保护规则：

- 内置分类不可修改/删除 → `510011`
- 分类下有模板时不可删除 → `510009`
- 复用内置分类标识 → `510010`（409）

**幂等验证**：重启两次后分类仍为 4 条。

## 3. 接口清单

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/feature-templates` | 列表，支持 `keyword`/`category`/`status` |
| POST | `/api/v1/feature-templates` | 创建，标识符可留空 |
| GET | `/api/v1/feature-templates/categories` | 分类列表（含模板数） |
| GET | `/api/v1/feature-templates/:id` | 详情 |
| PUT | `/api/v1/feature-templates/:id` | 更新，标识符不可改 |
| DELETE | `/api/v1/feature-templates/:id` | 删除，内置模板拒绝 |
| POST | `/api/v1/feature-template-categories` | 新建分类 |
| PUT | `/api/v1/feature-template-categories/:id` | 更新分类 |
| DELETE | `/api/v1/feature-template-categories/:id` | 删除分类 |

路由顺序：`/categories` 注册在 `/:id` 之前，静态段优先，不会被当成 id。

### 功能项可视化编辑

功能项不用 JSON 文本框，改为结构化行（序号 + 标识 + 名称 + 描述 + 上下移 + 删除），因为**顺序即客户端读取顺序**，文本框里挪动一项要数括号。

## 7. 实施中发现的问题

### 7.1 `binding:"required"` 与"留空自动生成"冲突

`FeatureTemplateCreateRequest.Identifier` 原本带 `binding:"required"`，导致留空时框架层直接返回 400，服务端的"留空则生成"逻辑永远走不到。

已移除该 binding，校验下移到 service 层。

### 7.2 列表页缺 `v-if` 导致表单渲染在折叠下方

`viewMode === 'form'` 时模板确实渲染了，但列表容器没有 `v-if`，导致表单出现在列表**下方**（需滚动才能看到），看起来像点击无响应。

客户页 `index.vue:3` 有 `v-if="viewMode === 'list'"`，我漏了。已补。

**这是照抄现有页面结构时的典型遗漏** —— 后端字段对齐做得很细，但页面级条件渲染没对齐。

### 7.3 分类编辑按钮缺少提交触发

初版 `CategoryManager` 的「编辑」按钮只调用 `startEdit` 填充表单，没有任何提交入口。已改为 `editingId` 有值时主按钮走 `submitEdit`，并加「取消」按钮。

### 7.4 i18n 命名空间被覆盖

用脚本合并 `products.*.json` 时，`navigation.menu.featureTemplates` 被上一轮循环覆盖掉。写 S2 时发现并补写。

**教训**：批量改 i18n JSON 后必须回读校验，不能只看脚本输出「已合并」。
