## 2. 企业版实测契约

```
GET /api/v1/product-offerings/{id}/public-key
→ {
    "product_id":   "deff875f-...",
    "product_code": "1111111111111",
    "public_key":   "-----BEGIN PUBLIC KEY-----\nMIIBIjANBgkq...\n-----END PUBLIC KEY-----\n"
  }
```

**关键实测结论**：

| 探测项 | 结果 |
| --- | --- |
| 公钥长度 | **451 字节**（RSA 2048，PKIX 格式） |
| 私钥端点 | **不存在**（404） |
| 密钥轮换端点 | **不存在**（404） |

企业版**只暴露公钥只读接口**，密钥在创建产品项时自动生成，无轮换能力。

本项目实现与之完全一致：公钥 **451 字节**，无私钥端点，无轮换端点。

## 3. 安全设计

### 3.1 私钥不泄露

| 保障手段 | 说明 |
| --- | --- |
| GORM tag `json:"-"` | 两个密钥字段均排除序列化 |
| 无私钥端点 | 仅 `/public-key` 返回公钥 |
| 无轮换端点 | 轮换会使已发放许可证全部失效 |

**实测**：详情接口、列表接口响应中 `PRIVATE KEY` 与 `signing_private_key` 出现次数均为 **0**。

### 3.2 跨产品隔离

密钥按产品项独立生成，单测直接断言隔离性：

```
TestVerifyRejectsOtherProductKey
  A 签名 → 用 B 的公钥验签 → 必须失败
```

### 3.3 签名算法一致性

复用既有 `VerifySignature` 使用的 **PSS 填充 + SHA-256**，未引入第二套约定。

单测覆盖 5 个场景：生成、签名验签闭环、内容篡改、跨产品验签、无效私钥。

## 7. 实施中的问题

### 7.1 误用 PKCS#1v15，与既有验签不兼容

初版 `SignWithPrivateKeyPEM` 用了 PKCS#1v15，但既有 `crypto.go` 的 `VerifySignature` 用的是 **PSS**。编译通过但运行时验签必然失败。

已改为 PSS 并复用既有验签实现。**教训：加签名前先读现有实现，不要凭偏好选算法。**

### 7.2 弹框插入打断 `v-if` 链

把 `<PublicKeyDialog>` 插在 `<ProductForm v-else-if>` 之前，导致 `v-else-if` 没有相邻的 `v-if`，Vue 编译报错「v-else/v-else-if has no adjacent v-if」。

已把 `ProductForm` 改为独立的 `v-if`（两者本就是互斥关系，不构成 else 链）。

### 7.3 日文文案出现替换字符

写 i18n 时 ja 文案混入 `U+FFFD` 替换字符。`perl -CSD` 正则未匹配到，改用 JSON 读出→改写→写回解决。

**注意**：这类问题必须回读校验 JSON 内容，光看脚本「已写入」的提示发现不了。
