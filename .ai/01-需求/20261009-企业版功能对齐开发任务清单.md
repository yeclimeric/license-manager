# 企业版功能对齐开发任务清单

> 目标：以敏捷模式在社区版上严格对齐企业版的功能与 UI，每个阶段结束时都是**可运行、可演示、可发布**的完整增量。
>
> 依据：企业版在线演示环境实测（接口 + 界面 + 前端产物），非文档推测。参考截图见 `docs/reference/ent-*.png`。

## 已确认决策（2026-10-09）

| #  | 决策                                        | 影响范围                                                 |
| -- | ----------------------------------------- | ---------------------------------------------------- |
| D1 | **引入 Casbin** 做 RBAC                      | S5 全部；`resource:action` 与实测 56 条一致                   |
| D2 | **登录响应版本化**：新增 `/api/v2/login`，保留 v1 不改动  | S5-5；前端 S5-9 切换                                      |
| D3 | **客户自助端本期不做**                             | 登录页隐藏「注册账号」链接；菜单不写入用户端管理分组                           |
| D4 | **产品 code 系统自动生成、不可更改；用户可设别名（alias）用于显示** | S1 与企业版 UI 有实质偏离，见 §0.3 与 S1-3                       |
| D5 | **不引入多租户**                                | 新表**不预留** `tenant_id`；`migration.go:93-106` 兼容分支保留不动 |
| D6 | **不做 i18n 响应统一改造**                      | 取消「全部响应按 `Accept-Language` 输出」方案，见下方专项              |
| D7 | **圆角统一 4px**                             | 对齐企业版；S0-3 改造 38 处硬编码 `0`（16 个文件）              |
| D8 | **Casbin 适配器直接查 `roles` 表**                 | 自定义 DB adapter，不用 file adapter，避免策略文件与 DB 双写          |

### D6 说明：取消 i18n 响应统一改造

原提案「所有接口响应 `message` 一律按 `Accept-Language` 输出」属于**新增改造**，判定为过度设计，予以取消。

调整后的口径：

| 项                 | 处理                                          |
| ----------------- | --------------------------------------------- |
| 现有 i18n 错误体系     | **保留不动**。三语包（`zh-CN`/`en-US`/`ja-JP`）已就绪，`middleware/i18n.go` 已实现语言协商，属既有资产 |
| 全量接口覆盖改造       | **不做**。不逐个接口补 `Accept-Language` 处理                        |
| 新增接口的 message    | 沿用项目现有写法 `i18n.GetErrorMessage("000000", lang)`，不新增机制         |
| `000000` 成功文案    | 保持现状（三语包已各有取值），**不改为硬编码英文**                          |

**与企业版的差异**：企业版 `/api/public/config` 硬编码 `"message":"success"`。本项目沿用 i18n 取值，默认回落 `zh-CN`「成功」。此差异属**有意保留**，不做对齐。

> ⚠️ **未执行的操作**：本次未删除既有的 i18n 错误体系。若真实意图是「彻底移除 message 的 i18n 机制」，那会同时移除三语错误提示能力，与 `.ai/_项目开发规范.md`「可预期业务错误使用项目现有多语言错误体系」冲突，需单独确认后再动。

### D7 圆角改造范围

现状 `frontend/src/` 中 `border-radius: 0` 硬编码共 **38 处，分布在 16 个文件**（实测统计）。需统一为 `4px`。

| 类别           | 文件数 | 处理                                    |
| ------------ | --- | ------------------------------------- |
| 全局样式令牌       | 3   | `variables.scss` 3 变量、`global.scss` 1 处 CSS 变量、`element-theme.scss` 6 处、`data-list.scss` 1 处 |
| 组件与视图 `<style>` | 13  | 逐处替换为 `4px` 或改为引用变量                 |

关键文件清单（`border-radius: 0` 分布）：

```
assets/styles/{global,data-list,element-theme}.scss
components/common/{MobileDateRange,JsonNode,JsonEditor}.vue
components/common/layout/{NavContent,Sidebar}.vue
views/{Dashboard,Login}.vue
views/Licenses/{LinenseList,LicenseSearch}.vue
views/Licenses/LicensesView/components/{AuthorizationInfo,BasicInfo,LicenseInfo,ChangeHistory}.vue
```

注意：

- `$border-radius-circle: 100%` 保持不变（圆形头像等场景）
- 建议统一引用 `$border-radius-base` 而非逐处写字面量，避免再次漂移
- 改后需全站截图核对（风险 R6）

### D8 Casbin 适配器选型

实现自定义 DB adapter 直接查 `roles` 表，**不使用 file adapter**。

理由：

- 权限数据的唯一可信源是 `roles` 表，界面改权限后立即生效，无需重启服务
- 避免策略文件（CSV）与 DB 双写导致的权限漂移
- 符合项目既定原则：单一可信源，避免魔法数字

实现要点：

- 实现 `persist.Adapter` 与 `persist.FilteredAdapter` 接口，按需加载策略
- 策略存储于 `roles` 表关联的权限字段，`super_admin` 可短路放行全部
- 权限变更后需使内存缓存失效，避免旧策略残留

#### S1-3 code 自动生成 + alias 别名方案（D4）

**背景**：企业版 `产品项编码` 由用户手填，提示「仅支持小写字母、数字、下划线和连字符，创建后不可修改」。本项目改为系统生成，用户另填别名。

| 项          | 设计                                                         |
| ---------- | ---------------------------------------------------------- |
| 字段         | `code`（系统生成，不可改）、`alias`（用户可填，可改，界面显示用）                    |
| 生成规则       | `po_` + 12 位小写字母数字，如 `po_a1b2c3d4e5f6`；随机不递增，避免泄露业务量级      |
| 唯一性        | 唯一索引；生成时重试至多 5 次                                           |
| `alias` 可空 | 为空时界面回落显示 `code`                                           |
| 显示规则       | 列表「产品项名称」列优先展示 `alias`，为空回落 `code`；`code` 仍在详情、「查看公钥」等场景可见 |
| 可改性        | `code` 服务层拒绝更新；`alias` 允许随时修改                              |
| 迁移影响       | 无存量数据，S1-1 建表时直接落地                                         |

**向导步骤 1 字段调整**（偏离企业版）：

| 企业版                 | 本项目                    |
| ------------------- | ---------------------- |
| `*产品项名称`（手填）        | `*产品项名称`（手填，保留）        |
| `*产品项编码`（手填 + 格式校验） | **移除手填**，创建后由系统生成并只读展示 |
| —                   | `别名（可选）`：用于界面显示，可后续修改  |
| `描述`                | `描述`（保留）               |

步骤说明文案需从企业版的「填写用于识别到的名称和系统使用的唯一编码…」改为说明别名用途与 code 自动生成规则。**具体文案在 S1 设计阶段确认**。

#### S5-5 v2 登录版本化方案（D2）

**背景**：企业版登录响应含 `permissions` 数组、JWT 无 `role` claim、`expires_in=604800`。社区版现状为 `user_info.role` + `expires_in=3600`，直接变更会破坏现有客户端。

| 端点                   | 策略                                                                            |
| -------------------- | ----------------------------------------------------------------------------- |
| `POST /api/v1/login` | **保持现状不改动**：返回 `user_info.role`，`expires_in=3600`，JWT 含 `role` claim          |
| `POST /api/v2/login` | **新增**：返回 `user_info` + `permissions`（56 条），`expires_in=604800`，JWT 不含 `role` |

过渡期双端并行，前端在 S5-9 切换到 v2。v1 是否下线另立需求，本期不移除。

#### S5-1 Casbin 适配器选型（D8）

**决策**：实现自定义 DB adapter 直接查 `roles` 表，**不使用 file adapter**。

理由：
- 权限数据的唯一可信源是 `roles` 表，界面改权限后立即生效，无需重启服务
- 避免策略文件（CSV）与 DB 双写导致的权限漂移
- 项目既定原则：单一可信源，避免魔法数字

实现要点：
- 实现 `persist.Adapter` 与 `persist.FilteredAdapter` 接口，按需加载策略
- 策略存储于 `roles` 表关联的权限字段，`super_admin` 可短路放行全部
- 权限变更后需使内存缓存失效，避免旧策略残留
