# License Manager 完整部署教程（前端 + 后端）

> 适用版本：当前 `main` 分支（含 `.env` 单点真相 + `deploy-prepare.sh`）。
> 文档覆盖三种部署方式、上线前安全清单、反向代理/HTTPS、升级/备份/故障排查。
> 部署者**唯一需要编辑的文件是仓库根目录的 `.env`**，无需手动改动 `backend/configs/config.prod.yaml`。

---

## 0. 架构概览

系统由三部分组成，全部通过 Docker 网络互联（也可裸机部署）：

| 组件 | 技术栈 | 容器内端口 | 宿主机映射 | 说明 |
| --- | --- | --- | --- | --- |
| MySQL 8.0 | 数据库 | 3306 | 3306（prod）/ 13306（1panel） | `utf8mb4`，唯一持久化数据 |
| 后端 Backend | Go 1.23 + Gin | 18888 | 18888（prod）/ 不暴露（1panel） | REST API、授权签名、RBAC |
| 前端 Frontend | Vue 3 + Nginx | 80 | 18880（避开 1panel 的 80） | SPA 静态资源 + `/api`、`/files` 反代 |

**请求链路**：浏览器 → 前端(Nginx:18880) → `/api/` 反代 → 后端(:18888) → MySQL(:3306)

**配置数据流（关键）**：`.env` 是敏感信息单点真相 → `MYSQL_PASSWORD`/`JWT_SECRET` 通过 compose 注入为环境变量 `DATABASE_PASSWORD`/`AUTH_JWT_SECRET` → 后端 `config.Load()` 用 `BindEnv` 覆盖 `config.prod.yaml` 中的占位值。**改一处，全链路生效，无需多文件同步。**

## 3. 部署配置（.env 单点真相）—— 核心

### 3.1 一键准备

```bash
bash scripts/deploy-prepare.sh
```

脚本自动完成：
1. 若 `.env` 不存在，从 `.env.example` 复制生成。
2. 若 `JWT_SECRET` 为空，生成强随机值（`openssl rand -hex 32`）写入 `.env`。
3. 若 `backend/configs/rsa_*.pem` 缺失，生成专属 RSA 密钥对。

### 3.2 编辑 `.env`（必做）

`.env.example` 内容如下，部署者**只需改此处**：

```bash
# MySQL配置
MYSQL_ROOT_PASSWORD=your-strong-root-password      # 必改：root 强口令
MYSQL_PASSWORD=your-strong-user-password           # 必改：业务库用户口令（同时也是后端 DB 口令）
MYSQL_PORT=3306

# 应用端口（宿主机映射）
BACKEND_PORT=18888
FRONTEND_PORT=18880

# JWT 签名密钥：可留空（deploy-prepare 已自动生成），或手动填 openssl rand -hex 32
JWT_SECRET=
```

字段说明：

| 变量 | 作用 | 是否必改 | 注入到哪里 |
| --- | --- | --- | --- |
| `MYSQL_ROOT_PASSWORD` | MySQL root 口令 | 必改 | MySQL 容器 |
| `MYSQL_PASSWORD` | 业务库 `license_user` 口令 | 必改 | MySQL 容器 **+** 后端 `DATABASE_PASSWORD` |
| `MYSQL_PORT` | MySQL 宿主机映射端口 | 一般默认 | 宿主机 |
| `BACKEND_PORT` | 后端宿主机映射端口 | 默认 18888 | 宿主机 |
| `FRONTEND_PORT` | 前端宿主机映射端口 | 默认 18880 | 宿主机 |
| `JWT_SECRET` | JWT 签名密钥 | 建议留空（脚本自动填） | 后端 `AUTH_JWT_SECRET` |

> 原理：`MYSQL_PASSWORD` 与 `JWT_SECRET` 经 compose 注入为 `DATABASE_PASSWORD` / `AUTH_JWT_SECRET`，后端 `config.go` 的 `BindEnv` 让环境变量优先于 `config.prod.yaml` 的占位值。**所以 `config.prod.yaml` 里的 `database.password` / `auth.jwt.secret` 无需手动改。**

### 3.3 上线前必改安全清单

部署到公网前必须逐项确认（否则存在密钥泄露 / 授权被伪造风险）：

1. **`MYSQL_PASSWORD` / `MYSQL_ROOT_PASSWORD`**：强口令。
2. **`JWT_SECRET`**：留空则由脚本生成；如手动设，用 `openssl rand -hex 32`。
   - 若 `.env` 未设 `JWT_SECRET`，后端会用 yaml 默认值触发**自动生成随机密钥**并打印 `[WARN]`；该密钥仅内存态，**重启即失效、所有令牌作废**，仅兜底、不可依赖。
3. **RSA 密钥对**：仓库自带的 `rsa_private_key.pem` 私钥已公开，**生产必须重新生成**（`deploy-prepare.sh` 在缺失时自动生成，或 `bash scripts/gen-rsa-keys.sh backend/configs 2048 --force`）。
4. **默认管理员**：首次启动自动建表并 seeding `admin / admin@123`，**登录后立即改密码**。
5. **端口**：1panel 自带 OpenResty 占用 `80/443`，前端务必走 `18880`，不要改回 `80`。
6. **暴露面**：公网仅暴露前端（经反代），后端 `18888` 不映射到宿主机（1panel 编排默认已不暴露）。
7. **Redis**：代码未使用，已从编排移除，无需部署。

## 4. 方式一：1panel 部署（推荐）

适用：服务器已装 1panel，希望面板可视化管理 + 一键 HTTPS。

1. **放代码**：把仓库 clone 到服务器某目录，例如 `/opt/1panel/docker/compose/license-manager`（即仓库根）。
2. **准备配置**：在该目录运行 `bash scripts/deploy-prepare.sh`，并按 §3.2 编辑 `.env`。
3. **创建编排**：1panel → **Docker → 编排 → 创建编排**；编排目录选该仓库根，compose 文件选 `docker-compose.1panel.yml`（或直接粘贴其内容）。
4. **启动**：点「创建并启动」，1panel 会执行 `docker compose up -d --build` 从源码构建后端/前端镜像（首次较慢）。
5. **暴露访问（二选一）**：
   - 快速验证：直接 `http://服务器IP:18880`（前端 Nginx 已内置 `/api/`、`/files/` 反代）。
   - 正式上线：1panel → **网站 → 创建网站 → 反向代理**，目标填 `http://127.0.0.1:18880`，再在网站内一键申请 **Let's Encrypt HTTPS**。一个反代即覆盖 SPA、API、文件下载。

> 1panel 编排中后端不暴露宿主机端口（仅 compose 内网），前端映射到 `18880` 高位端口，再由面板「网站」反代 + HTTPS，最干净。

## 5. 方式二：通用 Docker Compose（prod）

适用：无 1panel，纯命令行服务器。

```bash
cd /opt/app/license-manager

# 1) 准备 .env（首次）
bash scripts/deploy-prepare.sh
# 编辑 .env，至少改 MYSQL_ROOT_PASSWORD / MYSQL_PASSWORD

# 2) 构建并启动（首次及每次更新代码务必带 --build）
docker compose -f docker-compose.prod.yml up -d --build

# 3) 查看状态
docker compose -f docker-compose.prod.yml ps
docker compose -f docker-compose.prod.yml logs -f backend
```

- 前端：`http://服务器IP:18880`
- 后端 API：`http://服务器IP:18888/health`（仅内网/调试需要）
- MySQL：`localhost:3306`（容器内）；宿主机映射见 `.env` 的 `MYSQL_PORT`

正式访问建议同样加反向代理 + HTTPS（见 §8）。

## 6. 方式三：裸机 / 源码直接运行（无 Docker）

适用：开发环境、内网机器、或无法使用 Docker 的场景。需自行安装 MySQL 8、Go 1.23、Node 20 + pnpm。

### 6.1 数据库

```bash
# 自行安装 MySQL 8 并创建库/用户
mysql -uroot -p
CREATE DATABASE license_manager CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'license_user'@'%' IDENTIFIED BY 'your-strong-user-password';
GRANT ALL PRIVILEGES ON license_manager.* TO 'license_user'@'%';
FLUSH PRIVILEGES;
```

### 6.2 后端

```bash
cd backend

# 1) 准备本地配置
cp configs/config.local.yaml.example configs/config.local.yaml
# 编辑 host/username/password 指向你的 MySQL

# 2) 运行（从 backend/ 目录执行，config 路径用 configs/... 相对约定）
go run ./cmd -config configs/config.local.yaml
# 或编译后运行
go build -o ../bin/license-manager cmd/main.go && ../bin/license-manager -config configs/config.local.yaml
```

- 默认端口 `18888`，首次启动 `auto_migrate: true` 自动建表 + seeding 管理员。
- 注意：相对路径配置（`i18n.config_path`、`license.rsa.*_key_path`）从**当前工作目录**解析，务必在 `backend/` 下运行。

### 6.3 前端

```bash
cd frontend
pnpm install            # 必须用 pnpm，不是 npm/yarn
pnpm run build          # 产出 dist/（typecheck + 生产构建）

# 用 nginx 托管 dist/ 并反代 /api 到后端（见 §8 配置示例）
# 或开发模式：pnpm run serve（:3000，需 .env.development.local 指向后端）
```

## 8. 反向代理 + HTTPS（详细）

### 8.1 1panel「网站」反代（推荐）

1panel → 网站 → 创建网站（填域名）→ 反向代理 → 目标 URL 填 `http://127.0.0.1:18880` → 保存。
在网站设置里「HTTPS」→ 申请证书（Let's Encrypt，需域名已解析到服务器）→ 开启强制 HTTPS。

### 8.2 原生 Nginx 反代配置示例（无 1panel）

```nginx
server {
    listen 80;
    server_name license.example.com;
    # 先 HTTP 验证证书，验证通过后改为 443
    location / {
        proxy_pass http://127.0.0.1:18880;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

HTTPS 段（证书由 certbot 签发后）：

```nginx
server {
    listen 443 ssl;
    server_name license.example.com;
    ssl_certificate     /etc/letsencrypt/live/license.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/license.example.com/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:18880;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto https;
    }
}
```

> 前端容器内的 `nginx.conf` 已处理 `/api/`、`/files/` 到后端 `backend:18888` 的反代，外层反代只需把整个域名转发到 `:18880` 即可，无需在外层再拆 `/api`。

## 9. 升级与回滚

```bash
cd /opt/app/license-manager
git pull origin main                 # 拉取新代码

# 重新构建并滚动更新（compose 默认会按 depends_on 顺序重启）
docker compose -f docker-compose.prod.yml up -d --build

# 查看新镜像/容器状态
docker compose -f docker-compose.prod.yml ps
```

- **回滚**：`git checkout <上一个稳定 commit>` 后重新 `up -d --build`。数据库由 volume `mysql_data` 持久化，回滚代码不影响数据。
- 升级本质是「重新 build + 重启容器」，MySQL 数据卷与 `./logs`、`./data` 挂载不丢失。

## 10. 备份与恢复

### 10.1 数据库（唯一必须备份）

```bash
# 备份
docker compose -f docker-compose.prod.yml exec -T mysql \
  mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" license_manager > backup_$(date +%F).sql

# 恢复
docker compose -f docker-compose.prod.yml exec -T mysql \
  mysql -uroot -p"$MYSQL_ROOT_PASSWORD" license_manager < backup_2026-xx-xx.sql
```

### 10.2 密钥与配置

- `backend/configs/rsa_private_key.pem`：**私钥务必离线备份**（泄露 = 授权可被伪造）。
- `.env`：含所有口令，备份到安全位置，勿入仓库。
- `backend/configs/config.prod.yaml`：版本受控，无需单独备份。

> 建议把 `.env` 与 `rsa_private_key.pem` 纳入独立加密备份（如密码管理器 / 加密压缩包），不要与代码同仓。

## 12. 故障排查

| 症状 | 可能原因 | 排查/修复 |
| --- | --- | --- |
| MySQL 容器反复重启 | 旧数据目录权限/版本不兼容 | `docker compose logs mysql`；必要时 `down -v` 清空卷重建（**会丢数据，先备份**） |
| 后端启动 `log.Fatalf` 找不到 i18n/RSA | cwd 或挂载错误 | compose 已挂 `./backend/configs`；裸机需在 `backend/` 下运行；检查 `config.prod.yaml` 相对路径 |
| 后端连不上 DB | MySQL 未 healthy / 口令不一致 | `docker compose ps` 看 mysql healthy；确认 `MYSQL_PASSWORD` 已设且注入 `DATABASE_PASSWORD` |
| 前端白屏 / API 404 | 反代未覆盖 `/api/` | 检查外层反代转发到 `:18880`；容器内 `curl backend:18888/health` 验证 |
| JWT 报错「密钥无效/令牌失效」 | 用了内存态随机密钥并重启过 | 在 `.env` 设固定 `JWT_SECRET`（重新生成后所有旧令牌作废，需重新登录） |
| 80 端口冲突 | 1panel/OpenResty 已占 80 | 前端保持 `18880`，不要改回 `80`；用反代 + HTTPS |
| 前端 502 | 后端未起来 / 健康检查未过 | `docker compose ps` 看 backend 状态；`logs backend` 看启动错误 |

## 13. 附录：文件与端口清单

**关键文件**

| 路径 | 作用 |
| --- | --- |
| `docker-compose.prod.yml` | 通用生产编排（源码构建） |
| `docker-compose.1panel.yml` | 1panel 专用编排（前端 18880） |
| `.env` / `.env.example` | 部署者唯一需编辑的配置（单点真相） |
| `backend/configs/config.prod.yaml` | 后端生产配置（敏感项由 env 覆盖） |
| `scripts/deploy-prepare.sh` | 一键准备 `.env` + JWT + RSA |
| `scripts/gen-rsa-keys.sh` | 手动生成 RSA 密钥对 |
| `nginx.conf` | 前端容器内的反代配置（`/api/`、`/files/` → backend） |

**端口速查**

| 端口 | 服务 | 暴露建议 |
| --- | --- | --- |
| 3306 | MySQL（prod 宿主映射） | 仅内网 |
| 13306 | MySQL（1panel 宿主映射） | 仅内网维护 |
| 18888 | 后端 API | 仅内网（1panel 默认不暴露） |
| 18880 | 前端 Nginx | 公网经反代访问 |
| 80/443 | 1panel OpenResty | 面板自身，勿占用 |

---

**一句话总结**：`git clone` → `bash scripts/deploy-prepare.sh` → 改 `.env` 的 `MYSQL_*` 口令 → 选 1panel 编排或 `docker-compose.prod.yml` 启动 → 用反代 + HTTPS 暴露前端 → 登录改管理员密码。
