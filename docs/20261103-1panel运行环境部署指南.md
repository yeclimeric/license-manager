# 1panel「运行环境」部署指南（Go + 静态站点）

> 适用：已在 1panel 面板中，用「网站 → 运行环境（Go）」托管后端、「静态网站」托管前端。  
> 不使用 systemd，不使用 Docker 编排，进程由 1panel 运行环境管理。  
> 核心交付：**后端启动命令**（见 §3），以及配套的前端与反代配置。

---

## 0. 方案结构

```
1panel 面板
├─ 运行环境（Go）  license-backend   ← 后端 Go 程序，监听容器内 :18888
│    启动命令: sh deploy/1panel/start-backend.sh
│    环境变量: DATABASE_PASSWORD / AUTH_JWT_SECRET
│
└─ 静态网站        license-ui        ← 前端 dist/ 产物 + 反向代理 /api → 后端
     （或用「反向代理」类型指向后端端口）
```

**为什么需要启动脚本而不是直接写命令**：后端配置里的 `i18n.config_path` 与  
`license.rsa.*_key_path` 是**相对当前工作目录**解析的，不是相对配置文件位置。

| 启动 cwd         | 配置前缀             | 解析结果                    |
| -------------- | ---------------- | ----------------------- |
| `backend/`     | `configs/...`    | `backend/configs/...` ✅ |
| `backend/cmd/` | `../configs/...` | `backend/configs/...` ✅ |

容器里 1panel 设定的工作目录未必是 `backend/`，直接写 `./license-manager -config configs/config.local.yaml`  
有极大概率因找不到 i18n/RSA 文件而 `log.Fatalf` 启动失败。`start-backend.sh` 自动定位项目根并切到 `backend/`，消除这个不确定性。

## 1. 前置准备

### 1.1 服务器上放好代码

```bash
# 建议放在 1panel 便于管理的位置
mkdir -p /opt/1panel/runtime/license-manager
cd /opt/1panel/runtime/license-manager
git clone <你的仓库地址> .
git checkout main
```

### 1.2 准备配置与密钥

```bash
cd /opt/1panel/runtime/license-manager

# 一键完成：.env + JWT_SECRET + RSA 密钥替换 + 密钥 git 保护
bash scripts/deploy-prepare.sh

# 后端配置（从模板复制，路径前缀 configs/ 适配从 backend/ 启动）
cp backend/configs/config.local.yaml.example backend/configs/config.local.yaml
vi backend/configs/config.local.yaml
```

`config.local.yaml` 必改项：

```yaml
database:
  host: "127.0.0.1"        # MySQL 在宿主机则填 127.0.0.1；容器内需用宿主机内网 IP
  port: 3306
  username: "license_user"
  password: "你的强口令"     # 也可留空，用环境变量 DATABASE_PASSWORD 覆盖
  database: "license_manager"

auth:
  jwt:
    secret: "留空则用环境变量 AUTH_JWT_SECRET 覆盖"

server:
  mode: "release"           # 生产改 release
```

> ⚠️ 若 MySQL 跑在**另一个容器**里，`host` 不能填 `127.0.0.1`（那是容器自身）。  
> 填宿主机的内网 IP（如 `172.17.0.1` 或实际网卡 IP），并确保 MySQL 监听非 127.0.0.1。

### 1.3 预编译后端二进制（推荐，避免容器内编译）

```bash
cd /opt/1panel/runtime/license-manager/backend
go build -o ../bin/license-manager cmd/main.go
ls -lh ../bin/license-manager
```

容器内若无 Go 工具链，**必须**在宿主机预编译（脚本会自动检测并给出提示）。

### 1.4 Go 依赖缓存（容器内编译时）

1panel 运行环境是 Docker 容器，**容器可写层（如 `/root/go/pkg/mod`、`/root/.cache/go-build`）在容器重建后会丢失**，
导致每次重启都要重新下载依赖（实测首次编译约 70 秒，缓存命中后 0.7 秒）。

`deploy/1panel/start-backend.sh` 已自动把缓存重定向到项目目录：

```
<项目根>/.cache/mod     ← GOMODCACHE（依赖源码，约 270 MB）
<项目根>/.cache/build   ← GOCACHE（编译缓存，约 270 MB）
```

该目录在 1panel 中是**挂载目录**，容器重建后缓存仍在，无需重复下载。

若你手动编译（不用启动脚本），请自行指定缓存位置：

```bash
cd /opt/1panel/runtime/license-manager
mkdir -p .cache/mod .cache/build
export GOMODCACHE=$PWD/.cache/mod
export GOCACHE=$PWD/.cache/build
cd backend && go build -o ../bin/license-manager cmd/main.go
```

> ⚠️ `.cache/` 已加入 `.gitignore`（体积近 600 MB，**严禁提交**）。
> 宿主机预编译则不需要这套机制——不产生缓存，也没有重下依赖的问题。

## 2. 创建后端运行环境（1panel）

面板路径：**网站 → 运行环境 → 创建运行环境 → Go**

| 表单字段     | 填写值                                   | 说明                          |
| -------- | ------------------------------------- | --------------------------- |
| **运行目录** | `/opt/1panel/runtime/license-manager` | 项目根（含 `backend/`、`deploy/`） |
| **启动命令** | `sh deploy/1panel/start-backend.sh`   | 见 §3                        |
| **端口**   | `18888`                               | 后端监听端口                      |
| **环境变量** | 见下                                    | 注入敏感配置                      |

环境变量（逐条添加）：

```
DATABASE_PASSWORD=你的数据库强口令
AUTH_JWT_SECRET=你的JWT随机密钥
TZ=Asia/Shanghai
GIN_MODE=release
```

> `AUTH_JWT_SECRET` 用 `openssl rand -hex 32` 生成。留空的话后端会退回自动生成随机密钥，  
> **重启即失效、所有已签发令牌作废**，仅作兜底。

创建后点「启动」，用「查看日志」确认输出：

```
[start] 项目根: /opt/1panel/runtime/license-manager
[start] 使用已有可执行文件: /opt/1panel/runtime/license-manager/bin/license-manager
[start] 工作目录: /opt/1panel/runtime/license-manager/backend
[start] 配置文件: configs/config.local.yaml
[start] 监听地址: 0.0.0.0:18888
```

验证（宿主机执行，端口按 1panel 实际映射填写）：

```bash
curl -fsS http://127.0.0.1:18888/health
```

## 3. 启动命令（三选一）

### 方案 A（推荐）：用仓库内置脚本

启动命令填：

```
sh deploy/1panel/start-backend.sh
```

脚本自动完成：定位项目根 → 检查环境变量 → 检查配置文件 → 准备二进制 → `cd backend/` → `exec` 启动。

### 方案 B：宿主机预编译 + 手写命令

若不使用脚本，启动命令填（**注意 cwd**）：

```
cd backend && exec ../bin/license-manager -config configs/config.local.yaml
```

### 方案 C：容器内现场编译

启动命令填：

```
sh deploy/1panel/start-backend.sh
```

并**不要**预编译——脚本检测到无 `bin/license-manager` 且容器内有 `go` 时会自动编译。  
容器内无 Go 工具链时此方案不可用（脚本会明确报错）。

### ⚠️ 不要这样写

```
./license-manager -config configs/config.local.yaml
```

cwd 不确定 → 相对路径解析到错误位置 → 启动即失败。

### 启动命令的三个硬性要求

1. **必须 `exec`**：让后端成为容器主进程（PID 1），否则 1panel 停止/重启时信号传不到，进程可能残留。
2. **必须指定 `-config`**：否则程序按 `config.yaml` → `../configs/config.yaml` 顺序查找，容器里通常都不存在。
3. **cwd 必须是 `backend/`**：保证 `configs/...` 相对路径指向正确。

## 4. 前端部署（1panel 静态网站）

### 4.1 构建前端

在**有 Node 20 + pnpm 的机器**（可与后端同机）执行：

```bash
cd /opt/1panel/runtime/license-manager/frontend
pnpm install
VITE_OUTDIR=dist VITE_ADDRESS_BASE_URL=/ pnpm run build:prod
ls -la dist/     # 应有 index.html / static/ / favicon.svg
```



> ⚠️ 必须传 `VITE_OUTDIR=dist VITE_ADDRESS_BASE_URL=/`。  
> 仓库 `frontend/.env.production` 中是 `VITE_OUTDIR='production'` 与 `VITE_ADDRESS_BASE_URL='/production/'`，  
> 不覆盖会产出到 `frontend/production/` 且资源路径带 `/production/` 前缀，导致页面白屏。

### 4.2 放置产物

把 `dist/` 传到 1panel 静态站点的运行目录，例如 `/opt/1panel/www/sites/license-ui/index`：

```bash
sudo mkdir -p /opt/1panel/www/sites/license-ui/index
sudo rsync -a --delete frontend/dist/ /opt/1panel/www/sites/license-ui/index/
```

### 4.3 创建静态网站

面板路径：**网站 → 创建网站 → 静态网站**

| 字段           | 填写值                                      |
| ------------ | ---------------------------------------- |
| **代号**       | `license-ui`                             |
| **主域名**      | `license.example.com`（可加端口）              |
| **网站目录**     | `/opt/1panel/www/sites/license-ui/index` |
| **启用 HTTPS** | 开启并申请证书                                  |

### 4.4 配置 `/api` 反向代理（关键）

静态站点默认不会把 `/api` 转给后端，**必须配反代**，否则前端所有接口 404。

两种做法：

**做法一：编辑 1panel 生成的站点 OpenResty 配置**  
在站点的「配置」中，于 `server` 块内加入：

```nginx
location /api/ {
    proxy_pass http://127.0.0.1:18888;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_connect_timeout 60s;
    proxy_read_timeout 60s;
}

# Vue Router history 模式
location / {
    try_files $uri $uri/ /index.html;
}
```

**做法二：改用「反向代理」网站类型**  
网站 → 创建网站 → 反向代理 → 代理地址填 `http://127.0.0.1:18888`。  
但注意：后端只提供 API，不提供前端静态资源，**这种方式前端页面无法访问**。  
因此本项目**只能用做法一**（静态网站 + 站点内配 `/api` 反代）。

> 为什么反代到 `127.0.0.1:18888`：后端运行环境的端口已由 1panel 映射到宿主机。  
> 若 1panel 映射的是其他端口（如 `28888`），请同步修改 `proxy_pass`。  
> 前端用相对路径 `/api/...` 请求（生产 `VITE_API_BASE_URL` 为空），反代后浏览器始终同源，**完全绕开 CORS**。

## 6. 常见问题

| 现象                                                 | 原因                                | 处理                                                |
| -------------------------------------------------- | --------------------------------- | ------------------------------------------------- |
| 启动日志报 `failed to read config file`                 | 启动命令未带 `-config`                  | 用 §3 方案 A/B                                       |
| 报 `i18n ... no such file` / `RSA ... no such file` | cwd 不对，相对路径解析错位                   | 必须用启动脚本，或 `cd backend && ...`                     |
| 后端反复重启                                             | MySQL 连不上（容器内 `127.0.0.1` 指向容器自身） | `host` 填宿主机内网 IP；确认 MySQL 监听非 `127.0.0.1`         |
| 前端白屏                                               | 资源路径带 `/production/` 前缀           | 重新构建时传 `VITE_OUTDIR=dist VITE_ADDRESS_BASE_URL=/` |
| 前端接口全 404                                          | 站点未配 `/api` 反代                    | 见 §4.4                                            |
| 登录后刷新 404                                          | 缺 history 模式 fallback             | 站点配置加 `try_files $uri $uri/ /index.html`          |
| 停止运行环境后端口仍占用                                       | 启动命令未用 `exec`                     | 用 §3 方案 A/B                                       |
| 令牌每次重启都失效                                          | `AUTH_JWT_SECRET` 未设，用了自动生成的内存密钥  | 在运行环境环境变量中固定该值                                    |
| 容器每次重启都重新下载 Go 依赖                                | 依赖缓存在容器可写层，重建后丢失                | 确认启动脚本输出 `[start] Go 缓存目录: ...`；手动编译时设 `GOMODCACHE`/`GOCACHE` 指向项目 `.cache/`（见 §1.4） |
| `unbound variable` 报错                                     | shell 变量后紧跟中文全角标点（如 `$CACHE_DIR（`）| 已在新版脚本修复；自行修改脚本时变量与全角标点间加空格或用 `${VAR}`          |

## 7. 更新与回滚

```bash
cd /opt/1panel/runtime/license-manager
git pull

# 后端：重新编译
cd backend && go build -o ../bin/license-manager cmd/main.go && cd ..
# 然后在 1panel 面板点「重启」

# 前端：重新构建并同步
cd frontend && pnpm install
VITE_OUTDIR=dist VITE_ADDRESS_BASE_URL=/ pnpm run build:prod
sudo rsync -a --delete dist/ /opt/1panel/www/sites/license-ui/index/
```

> ⚠️ `git pull` 前确认 `backend/configs/rsa_private_key.pem` 未被改动。  
> `scripts/deploy-prepare.sh` 已为它设置 `git skip-worktree`，正常不会被覆盖。  
> 验证：`git ls-files -v backend/configs/rsa_private_key.pem`，前缀 `S` 表示已保护。
