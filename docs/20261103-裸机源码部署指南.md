# 裸机源码部署指南（前后端分离 · 已有 MySQL）

> 适用：代码已 clone 到服务器、本机/远程已有 MySQL 8、不使用 Docker。
> 核心约束：**部署者只需改 1 个后端配置文件 + 1 个 nginx 配置**，其余按命令执行。
> 与 Docker 方式的差异全部集中在文末「§12 与 Docker 部署的 4 处关键差异」。

---

## 0. 拓扑与端口

> 仓库已内置本方案所需的两份配置文件：
> - `deploy/systemd/license-manager.service` — 后端 systemd unit 模板
> - `deploy/nginx/license-manager.conf` — 前端托管 + `/api` 反代（宿主机可用版）
>
> 直接复制改路径即可，无需手写。

```
                        ┌─────────────────────────────┐
                        │  前端机（可与后端同机）      │
   浏览器 ──HTTPS──▶ Nginx :443                     │
                        │  root /var/www/license-ui   │
                        │  /api/  ──反代──▶ 后端 :18888 │
                        └──────────────┬──────────────┘
                                       │
                        ┌──────────────▼──────────────┐
                        │  后端机（Go binary, systemd） │
                        │  license-manager :18888      │
                        │  MySQL :3306                 │
                        └─────────────────────────────┘
```

| 端口 | 用途 | 暴露范围 |
| --- | --- | --- |
| 443/80 | Nginx（前端 + `/api` 反代） | 公网 |
| 18888 | 后端 API | **仅内网/本机**（前端机反代用） |
| 3306 | MySQL | **仅本机** |

## 2. MySQL：建库建用户

```bash
mysql -uroot -p
```

```sql
-- 字符集必须 utf8mb4（授权码/证书含中文与 emoji）
CREATE DATABASE license_manager CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

-- 本机部署
CREATE USER 'license_user'@'127.0.0.1' IDENTIFIED BY '你的强口令';
GRANT ALL PRIVILEGES ON license_manager.* TO 'license_user'@'127.0.0.1';
```

```bash
mysql -h127.0.0.1 -ulicense_user -p -e "SELECT 1; SHOW DATABASES LIKE 'license_manager';"
```

## 3. 后端配置（唯一需要编辑的配置文件）

### 3.1 创建配置文件

```bash
cd /path/to/license-manager/backend
cp configs/config.local.yaml.example configs/config.local.yaml
```

> `backend/configs/config.local.yaml` 已在 `.gitignore` 中，不会误提交生产口令。
> **必须用 `config.local.yaml`（路径前缀 `configs/`），不能用 `config.prod.yaml`**——后者路径为 `../configs/`，只适配容器内 cwd=`backend/cmd/` 的场景。这是裸机部署最常见的启动失败原因。

### 3.2 编辑 `configs/config.local.yaml`

逐项核对：

| 配置项 | 改为 | 说明 |
| --- | --- | --- |
| `server.mode` | `"release"` | 生产关调试 |
| `database.host` | `"127.0.0.1"`（同机）或 MySQL 真实 IP | 远程 MySQL 填 IP |
| `database.port` | `3306` | |
| `database.username` | `"license_user"` | 第 2 步创建 |
| `database.password` | 你的强口令 | 或用环境变量覆盖，见 3.3 |
| `database.database` | `"license_manager"` | |
| `database.charset` | `"utf8mb4"` | 保持 |
| `auth.jwt.secret` | `openssl rand -hex 32` 的输出 | **必改**，见 3.3 |
| `log.level` | `"info"` | |
| `log.format` | `"json"` | |
| `i18n.config_path` | `"configs/i18n/errors"` | **保持不变**（相对 `backend/`） |
| `license.rsa.private_key_path` | `"configs/rsa_private_key.pem"` | **保持不变** |
| `license.rsa.public_key_path` | `"configs/rsa_public_key.pem"` | **保持不变** |

> ⚠️ `i18n.config_path` 与 `license.rsa.*_key_path` 是**相对当前工作目录**解析的，不是相对配置文件位置。后端必须从 `backend/` 目录启动（systemd 已配 `WorkingDirectory`）。

### 3.3 口令与密钥：优先用环境变量

后端已支持两个环境变量覆盖 yaml（`BindEnv`），比手改文件更安全（不落盘到版本库）：

| yaml 键 | 环境变量 |
| --- | --- |
| `database.password` | `DATABASE_PASSWORD` |
| `auth.jwt.secret` | `AUTH_JWT_SECRET` |

生成 JWT 密钥：

```bash
openssl rand -hex 32
```

在 systemd 的 `EnvironmentFile` 中注入（见 §5），yaml 里保留占位即可。

> 兜底行为：若 `auth.jwt.secret` 仍是默认值/空值，后端启动会**自动生成随机密钥**并打 `[WARN]`。该密钥**仅在内存中，重启即失效、所有已签发令牌作废**，不可作为生产常态。

## 4. 生成 RSA 密钥对（必须）

仓库自带的 `rsa_private_key.pem` 私钥**已随仓库公开**，生产必须重新生成，否则授权文件签名可被伪造。

```bash
cd /path/to/license-manager
bash scripts/gen-rsa-keys.sh backend/configs 2048 --force
```

验证：

```bash
openssl rsa -in backend/configs/rsa_private_key.pem -check -noout
head -1 backend/configs/rsa_private_key.pem   # 应为 -----BEGIN RSA PRIVATE KEY-----
head -1 backend/configs/rsa_public_key.pem    # 应为 -----BEGIN PUBLIC KEY-----
```

> 私钥仅服务器持有；`rsa_public_key.pem` 需分发给客户端用于验签。
> 私钥丢失 = 已签发的授权文件全部无法验签，需谨慎备份。

## 5. 编译后端 + systemd 托管

### 5.1 编译

```bash
cd /path/to/license-manager/backend
go build -o ../bin/license-manager cmd/main.go
ls -lh ../bin/license-manager
```

### 5.2 创建密钥文件

```bash
sudo mkdir -p /etc/license-manager
sudo tee /etc/license-manager/license-manager.env >/dev/null <<EOF
DATABASE_PASSWORD=你的数据库强口令
AUTH_JWT_SECRET=你的JWT随机密钥
EOF
sudo chmod 600 /etc/license-manager/license-manager.env
```

### 5.3 systemd unit

仓库已内置模板 `deploy/systemd/license-manager.service`，复制后改两处路径即可：

```bash
sudo cp /path/to/license-manager/deploy/systemd/license-manager.service /etc/systemd/system/license-manager.service
sudo vi /etc/systemd/system/license-manager.service
# 改两处 /path/to/license-manager 为实际克隆目录（用 pwd 取绝对路径）：
#   WorkingDirectory=/path/to/license-manager/backend
#   ExecStart=/path/to/license-manager/bin/license-manager -config configs/config.local.yaml
```

模板内容（供参考）：

```ini
[Unit]
Description=License Manager API
After=network.target mysql.service
Wants=mysql.service

[Service]
Type=simple
User=www-data
Group=www-data

# 必须为 backend/ 目录：i18n 与 RSA 路径是相对 cwd 解析的
WorkingDirectory=/path/to/license-manager/backend
ExecStart=/path/to/license-manager/bin/license-manager -config configs/config.local.yaml

EnvironmentFile=/etc/license-manager/license-manager.env
Environment=TZ=Asia/Shanghai
Environment=GIN_MODE=release

Restart=always
RestartSec=5
StandardOutput=journal
StandardError=journal

[Install]
WantedBy=multi-user.target
```

> `WorkingDirectory` 里的路径与 `ExecStart` 里的路径请替换为实际克隆目录（用 `pwd` 取绝对路径）。
> `User=www-data` 需对配置目录有读权限：`sudo chown -R www-data:www-data /path/to/license-manager/backend/configs`。

### 5.4 启动

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now license-manager
sudo systemctl status license-manager
journalctl -u license-manager -f --no-pager
```

## 6. 验证后端

```bash
curl -fsS http://127.0.0.1:18888/health
curl -fsS http://127.0.0.1:18888/api/public/config   # 免鉴权公开接口
```

预期返回 JSON（`code: 000000`）。Swagger：`http://127.0.0.1:18888/swagger/index.html`。

若启动失败，按序排查：

| 报错 | 根因 | 修复 |
| --- | --- | --- |
| `failed to read config file` | 路径/文件名不对 | 必须 `-config configs/config.local.yaml` 且 cwd=`backend/` |
| `i18n ... no such file` | 用了 `config.prod.yaml` 的 `../configs/` 路径 | 换回 `config.local.yaml` |
| `RSA ... no such file` | 同上，或未执行第 4 步 | 执行第 4 步 |
| `Access denied for user` | MySQL 账号/权限 | 复核第 2 步；远程 MySQL 还需 `bind-address` 与防火墙 |
| `Access denied for database` | MySQL 未授权该库 | `GRANT ALL ON license_manager.*` |
| 反复重试连不上 DB | MySQL 未就绪 | `systemctl status mysql`；代码会重试 200 次 × 3s |
| `[WARN] auth.jwt.secret 为默认/占位值` | 未配 `AUTH_JWT_SECRET` | 按 3.3 写入 EnvironmentFile |

## 7. 构建前端

```bash
cd /path/to/license-manager/frontend
pnpm install
```

### 7.1 ⚠️ 必须覆盖构建环境变量

仓库的 `frontend/.env.production` 中：

```
VITE_OUTDIR='production'
VITE_ADDRESS_BASE_URL = '/production/'
```

若直接 `pnpm run build:prod`，产物会落到 `frontend/production/`，且资源路径带 `/production/` 前缀 —— 与 nginx 根目录托管不匹配。**必须覆盖为 `dist` + `/`**（与 `Dockerfile.frontend` 中的 `ENV` 一致）：

```bash
VITE_OUTDIR=dist VITE_ADDRESS_BASE_URL=/ pnpm run build:prod
```

验证产物：

```bash
ls frontend/dist/                 # 应有 index.html / static/ / favicon.svg
grep -o '/static/js/[^"]*' frontend/dist/index.html | head -2   # 应为 /static/... 根路径
```

### 7.2 部署到 Nginx 站点目录

```bash
sudo mkdir -p /var/www/license-ui
sudo rsync -a --delete frontend/dist/ /var/www/license-ui/
sudo chown -R www-data:www-data /var/www/license-ui
```

## 8. Nginx 配置（前端托管 + `/api` 反代）

### 8.1 ⚠️ 不能直接用仓库的 `nginx.conf`

仓库 `nginx.conf` 是**容器专用**，两处裸机不可用：

1. `resolver 127.0.0.11 ipv6=off;` —— `127.0.0.11` 是 Docker 内嵌 DNS，宿主机不存在 → 反代全部 502。
2. `set $backend_upstream http://backend:18888;` + 变量式 `proxy_pass` —— 依赖变量 + resolver 才能解析容器名。

裸机版直接用静态 upstream（无需 resolver）。仓库已内置可用配置 `deploy/nginx/license-manager.conf`：

```bash
sudo cp /path/to/license-manager/deploy/nginx/license-manager.conf /etc/nginx/sites-available/license-manager
sudo vi /etc/nginx/sites-available/license-manager
# 改两处：
#   server_name license.example.com;          → 你的域名（无域名用 _）
#   proxy_pass http://127.0.0.1:18888;         → 前后端分离时改为后端机内网 IP:18888

sudo ln -sf /etc/nginx/sites-available/license-manager /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
```

配置内容（供参考）：

```nginx
server {
    listen 80;
    server_name license.example.com;

    root /var/www/license-ui;
    index index.html;

    # Vue Router history 模式
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 前端 API 反代到后端（同源，无需 CORS）
    location /api/ {
        proxy_pass http://127.0.0.1:18888;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_connect_timeout 60s;
        proxy_read_timeout 60s;
    }

    # 静态资源长缓存
    location ~* \.(js|css|png|jpg|jpeg|gif|ico|svg|woff|woff2|ttf)$ {
        expires 1y;
        add_header Cache-Control "public, immutable";
        access_log off;
    }
}
```

### 8.2 前后端分离时的差异

后端在另一台机器时：

```nginx
location /api/ {
    proxy_pass http://后端机内网IP:18888;   # 如 192.168.1.20:18888
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

**关键点**：前端 `VITE_API_BASE_URL` 生产环境为空字符串，axios 请求走**相对路径** `/api/xxx`。只要用 nginx 反代，浏览器始终同源访问，**完全绕开 CORS**（后端的 `Access-Control-Allow-Origin: *` 与 `withCredentials: true` 组合本就不符合规范，不要依赖跨域直连）。

同时在后端机放行：

```bash
sudo ufw allow from <前端机IP> to any port 18888 proto tcp
# MySQL 只允许后端机本地，不要对前端机开放 3306
```

## 12. 与 Docker 部署的 4 处关键差异（务必检查）

| # | 项 | Docker | 裸机（本文） |
| --- | --- | --- | --- |
| 1 | 后端配置 | `config.prod.yaml`，路径 `../configs/`，cwd=`backend/cmd/` | **`config.local.yaml`，路径 `configs/`，cwd=`backend/`** |
| 2 | 前端构建 | `ENV VITE_OUTDIR=dist VITE_ADDRESS_BASE_URL=/` | **必须命令行传同样的 env**，否则产物落 `production/` 且路径带 `/production/` |
| 3 | nginx 反代 | `resolver 127.0.0.11` + 变量 proxy_pass（容器 DNS） | **必须改静态 `proxy_pass http://IP:18888`**，否则 502 |
| 4 | 敏感配置 | compose `environment` 注入 | systemd `EnvironmentFile` 注入 |

> 后端日志只输出到 **stdout**（`logger.SetOutput(os.Stdout)`），不写文件 —— 用 `journalctl -u license-manager` 查看即可，无需建 `logs/` 目录。
